Code Generation (~~)

Generate valid NAIDE code from natural language instructions. No AI, no network, no dependencies — pure pattern matching + template composition with self-healing parser validation. Runs in microseconds.

CLI Usage

Use ~~ or gen followed by a quoted instruction:

naide ~~ "REST API for users with auth"
naide gen "todo app with database"
naide ~~ "Discord bot with hello command"
naide ~~ "blog app with auth and websocket"
naide ~~ "CLI tool"
naide gen "chat app"

Japanese instructions are fully supported:

naide ~~ "ユーザー管理APIを認証付きで"
naide ~~ "掲示板アプリ"
naide ~~ "商品管理のフルスタックアプリ"
naide ~~ "チャットアプリ"

Write the output to a file with -o:

naide ~~ "REST API for users" -o app.naide

Output Example

naide ~~ "REST API for users with auth" generates:

schema User:
  id       auto
  name     str required
  email    str required email
  password str required min(8)

db "data/"

server user port 3000:
  cors "*"
  crud "/api/users" User
  auth JWT_SECRET:
    protect "/api/*"
    public "/api/auth/*"

  get "/api/health" (req, res):
    ret {status: "ok", users: UserStore.count()}

Inline Directives

Use ~~ inside .naide files. The directive is expanded at compile time, before parsing:

# app.naide
~~ "REST API for users with auth"

# You can mix with hand-written code
fn customRoute(req, res):
  ret {custom: true}

Debug the expansion with --expand:

naide --expand app.naide

API Usage

Use programmatically in JavaScript/TypeScript:

import { generate } from 'naider';

const result = generate("REST API for users with auth");

console.log(result.code);      // generated NAIDE source code
console.log(result.valid);     // true (parser-validated)
console.log(result.intents);   // ['server', 'schema', 'crud', 'auth', 'database']
console.log(result.schema);    // 'User'
console.log(result.port);      // 3000
console.log(result.fixed);     // false (true if auto-repaired)
console.log(result.repairs);   // [] (list of auto-fix descriptions)
console.log(result.suggestion);// null (hint text if match was weak)

Override parameters:

const result = generate("REST API", {
  port: 8080,
  schemaName: "Product",
  fields: [
    { name: "id", type: "auto", modifiers: [] },
    { name: "title", type: "str", modifiers: ["required"] },
    { name: "price", type: "int", modifiers: ["required"] },
  ]
});

MCP Server

The naide_generate tool is available via the MCP server for AI agent integration:

naide-mcp

The tool accepts instruction, port, and schemaName parameters, and returns generated code with metadata.

Self-Healing Validation

Generated code is validated against the actual NAIDE parser. If a parse error occurs, the engine auto-repairs it (up to 5 retries):

  • Missing : at the end of block headers
  • Unexpected indentation (adds colon to previous line)
  • Reserved keyword used as identifier (renames with suffix)
  • Structural issues (removes problematic lines)

Repairs are logged in result.repairs:

["L5: added missing ':' at end of block header",
 "L8: renamed reserved word 'post' → 'postApp'"]

Field Specification

Add with followed by field names to customize the schema:

naide ~~ "REST API for users with name email age role"

Field types are auto-inferred from names: id→auto, email→str+email, age→int, done→bool, created→auto. Without with, preset fields are used based on the entity name.

Examples

Todo App

naide ~~ "todo app with auth"

Generates: schema Todo (id, title, done) + db + server with CRUD + JWT auth

Discord Bot

naide ~~ "Discord bot with hello and help commands"

Generates: bot block with discord platform, event handlers for each command

Fullstack E-commerce

naide ~~ "shop app with sqlite"

Generates: schema Product + SQLite db + server with CRUD + auth

Japanese: User Management

naide ~~ "ユーザー管理APIを認証付きで"

Generates: schema User + db + server with CRUD + JWT auth (same as English equivalent)
