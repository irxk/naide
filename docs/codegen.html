Code Generation (~~)

Generate valid NAIDE code from natural language instructions. No AI, no network, no dependencies — pure pattern matching + template composition with self-healing parser validation. Runs in microseconds.

CLI Usage

Use ~~ or gen followed by a quoted instruction:

naide ~~ "REST API for users with auth"
naide gen "todo app with database"
naide ~~ "Discord bot with hello command"
naide ~~ "blog app with auth and websocket"
naide ~~ "users and products and orders with auth"
naide gen "chat app"

Japanese instructions are fully supported:

naide ~~ "ユーザー管理APIを認証付きで"
naide ~~ "掲示板アプリ"
naide ~~ "ECサイト"
naide ~~ "チャットアプリ"

Write the output to a file with -o:

naide ~~ "REST API for users" -o app.naide

Multi-Entity Support

Specify multiple entities separated by and, &, or ,. The engine detects parent-child relationships and auto-injects foreign keys:

naide ~~ "users and products and orders with auth"

This generates 3 schemas (User, Product, Order), detects that User → Order and Product → Order, and adds user_id and product_id FK fields automatically. Each entity gets full CRUD, paginated list, soft delete, batch operations, nested routes, and tests.

Composite keywords also expand to multiple entities:

naide ~~ "shop"       # User + Product + Order
naide ~~ "ECサイト"    # User + Product + Order
naide ~~ "crm"        # User + Contact + Deal + Activity
naide ~~ "sns"        # User + Post + Comment + Message + Notification

Project Mode

Generate a complete project directory with all supporting files:

naide ~~ "e-commerce app with auth" --project

This creates a directory with:

  • app.naide — Main NAIDE source code
  • package.json — With dev/test/seed scripts
  • .env — Environment variables (JWT_SECRET, PORT)
  • .gitignore — node_modules, .env, data/
  • Dockerfile + .dockerignore — Docker container support
  • README.md — Full API documentation with endpoints
  • openapi.json — OpenAPI 3.0.3 specification
  • admin.html — Admin dashboard with CRUD forms, search, stats
  • client.mjs — JavaScript API client with typed functions

File Write Mode

Write generated code directly to a .naide or .nx file:

naide ~~ "REST API for users with auth" --write app.naide
naide ~~ "todo app" --write todo.nx
naide ~~ "users API" --write app.naide --replace

Without --replace, the engine merges intelligently — avoids duplicate schemas and servers. With --replace, the file is overwritten completely.

Utility Functions

Standard response helpers and input sanitization:

fn ok(any data, any meta) → {ok: true, data, meta}
fn err(str message, int code) → {ok: false, error: message, code}
fn sanitize(str input) → stripped HTML tags

Audit Log

When auth is enabled, an AuditLog schema and auditLog() function are generated for tracking actions.

Seed Function

A fn seed() function is generated with sample data for each entity, callable via npm run seed in project mode.

Auto-Generated Tests

CRUD test suites are generated for each entity — create, find, list, remove with assertions.

Inline Directives

Use ~~ inside .naide files. The directive is expanded at compile time, before parsing:

# app.naide
~~ "REST API for users with auth"

# You can mix with hand-written code
fn customRoute(req, res):
  ret {custom: true}

Debug the expansion with --expand:

naide --expand app.naide

API Usage

Use programmatically in JavaScript/TypeScript:

import { generate, generateProject } from 'naider';

const result = generate("users and products with auth");

console.log(result.code);          // generated NAIDE source code
console.log(result.valid);         // true (parser-validated)
console.log(result.intents);       // ['server', 'schema', 'crud', 'auth', 'database']
console.log(result.entities);      // ['User', 'Product']
console.log(result.relationships); // [{parent:'User', child:'Product', fk:'user_id'}]
console.log(result.port);          // 3000
console.log(result.fixed);         // false (true if auto-repaired)
console.log(result.repairs);       // [] (list of auto-fix descriptions)
console.log(result.analysis);      // {entities, relationships, plan, ...}

// Full project generation
const project = generateProject("e-commerce with auth");
project.files.forEach(f => console.log(f.path));
// app.naide, package.json, .env, Dockerfile, README.md, openapi.json, admin.html, client.mjs, ...

MCP Server

The naide_generate tool is available via the MCP server for AI agent integration:

naide-mcp

The tool accepts instruction, port, and schemaName parameters, and returns generated code with metadata.

Self-Healing Validation

Generated code is validated against the actual NAIDE parser. If a parse error occurs, the engine auto-repairs it (up to 5 retries):

  • Missing : at the end of block headers
  • Unexpected indentation (adds colon to previous line)
  • Reserved keyword used as identifier (renames with suffix)
  • Structural issues (removes problematic lines)

Repairs are logged in result.repairs:

["L5: added missing ':' at end of block header",
 "L8: renamed reserved word 'post' → 'postApp'"]

Field Specification

Add with followed by field names to customize the schema:

naide ~~ "REST API for users with name email age role"

Field types are auto-inferred from names: id→auto, email→str+email, age→int, done→bool, created→auto. Without with, preset fields are used based on the entity name.
