CLI Reference

The naide command-line tool compiles, runs, tests, and manages NAIDE projects.

Basic Usage

$ naide <file>              # Compile and run
      $ naide --native app.naide    # Execute directly, without JavaScript generation
      $ naide native app.naide     # Experimental direct NAIDE AST interpreter
$ naide <file> -o out.mjs   # Compile to file
$ naide <file> -w           # Watch mode (auto-recompile)

naide --native and naide native do not generate JavaScript. JavaScript applications can embed the interpreter with import { runNativeAsync } from 'naider/native'. The direct interpreter supports core constructs, model declarations with new, defaulted fields, custom init(params): initializers, self methods, initialized static fields, static fn/static fn.async methods and inheritance, async methods, single inheritance, and super.method() calls from instance or static overrides. Static self refers to the called model, including inherited methods; async static overrides can use await super.method(). It also supports enums (frozen objects with zero-based member values), synchronous and asynchronous generator functions, lambdas, and model methods with standalone yield statements and yield* delegation; async generators can await while producing values. Nested yield expressions are not supported yet. Async functions and async generators support for await value of iterable: for synchronous or asynchronous iterables; synchronous execution rejects this loop form. It also supports fn.async, await, await.all, task coordination (task.spawn, task.all, task.race, bounded task.map, task.sleep), and bounded asynchronous collection operations (mapAsync, filterAsync, forEachAsync) plus sequential reduceAsync. These collection operations consume synchronous or asynchronous iterables, preserve mapping/filtering order, and count input consumption against the configured step limit. Synchronous iterable helpers include map, filter, reduce, find, some, every, flatMap, unique, enumerate, zip, and sum; each and for ... of handle lists, strings, maps, sets, and generator results. Bounded/FIFO task channels use task.channel; cancellation uses task.controller(), and timeouts use task.withTimeout. Channel send/receive accept optional AbortSignals and remove cancelled waiters from the queue. Cancellation uses cooperative AbortSignals; operations that ignore a signal may continue after timeout. Runtime errors include NAIDE source locations and function/file frames when available. It supports relative .naide imports and installed NAIDE packages in node_modules when the package has a naide.pkg.json with an in-package .naide main entry. Package lookup walks parent directories; subpaths must be explicitly mapped by exact keys in the manifest's exports object to in-package .naide files. Symlink targets escaping the package are rejected. Module imports are cached; cycles are rejected. Async file I/O is available via io.readText, io.writeText, io.appendText, io.exists, and io.listDir; paths are confined to the entry file's directory. HTTP requests use http.request, http.get, and http.post with the host Fetch implementation; only HTTP(S) URLs are accepted. Network access has no host allowlist and is not an OS-level sandbox. Task scheduling is cooperative and does not provide CPU parallelism. JavaScript-only npm packages, Node.js built-ins, arbitrary JavaScript classes, and framework declarations remain unsupported. This is not a CPU-parallel VM or a performance claim; bytecode/JIT work is future work. Use --steps <maximum> to set an execution budget. The default runner and REPL are unchanged.

Iterable queries find/some/every and prefix operations first/take/takeWhile short-circuit and close iterators. The async equivalents are firstAsync, findAsync, someAsync, everyAsync, takeAsync, and takeWhileAsync. Counts must be non-negative safe integers, and iterator reads count toward the execution step budget.

The native runtime exposes limited host context as runtime.args, runtime.cwd, runtime.platform, runtime.arch, and runtime.exitCode. Arguments follow --; environment variables are hidden unless explicitly selected with --env NAME (repeatable), then read through runtime.env. It intentionally does not expose arbitrary process access or shell execution.

$ naide native app.naide --env APP_MODE -- input.txt
# In app.naide: runtime.env.get("APP_MODE"), runtime.args

Compilation Targets

$ naide app.naide                    # Node.js (default)
$ naide app.naide --target python     # Python / Flask
$ naide app.naide --target bun        # Bun runtime
$ naide app.naide -t py               # Short alias
TargetOutputServer
node (default)JavaScript (.mjs)Express
python / pyPython (.py)Flask
bunJavaScript (.js)Bun.serve()

Type Checking

$ naide --check app.naide            # Type-check only, no run
$ naide check app.naide              # Same as above

Debugging

$ naide app.naide --debug             # Launch with Chrome DevTools
$ naide app.naide -d                  # Short alias

Opens node --inspect-brk for step-through debugging in Chrome DevTools.

Testing

$ naide test tests.naide             # Run test file

Package Ecosystem

$ naide pkg init                     # Initialize package.json
$ naide pkg install <name>           # Install a package
$ naide pkg publish                  # Publish to npm
$ naide pkg list                     # List installed packages

Deployment

$ naide deploy                       # Generate Dockerfile

Generates a production Dockerfile with multi-stage build.

REPL

$ naide                              # Interactive REPL
NAIDE v2.0.2 REPL
> str name = "World"
> log "Hello, {name}!"
Hello, World!
